# 云机闭环控制与验收

本文说明云机 + GHUB 场景的控制边界、标定流程和回放门禁。目标环境示例为
2560×1440、144 Hz、约 600 DPI、游戏灵敏度 0.4。实现保持全局常开，不依赖
窗口白名单、桌面黑名单或前台进程判断。

## 什么是云机（新手必读）

云机（云电脑/云游戏）指游戏和桌面运行在远端云电脑，而 VisionForge、鼠标驱动
（GHUB 等）和云机客户端都运行在用户本机。常见平台包括顺网云/AirLinks、腾讯云游戏、
网易云游戏、悠悠远程云电脑等。使用云机前应先关闭本机游戏，避免本机窗口与云机画面
混淆；然后在“调节 > 云机（可选）”开启运行场景，依次填写平台名称（任意非空名称，
例如 shunwang、airlinks、腾讯云游戏）、云游戏画面分辨率、GHUB 鼠标 DPI 和游戏内
灵敏度，最后完成一次约 20 秒标定。平台名称会规范化后纳入标定环境指纹：名称变化后必须重新
标定；已有 shunwang 画像在名称保持 shunwang 时继续有效。

## 分层与契约

控制链路保持单向依赖：

1. GUI/配置层只收集环境参数和高层画像。
2. `effective_control_policy` 把画像、个人模板和标定摘要编译为不可变有效策略。
3. 视觉层只提交 `ControlObservation`；旧 `submit(...)` 作为一个版本的兼容适配器。
4. `cloud_control_runtime` 负责延迟队列、响应学习和无视觉进展监视。
5. `runtime_controller` 负责 Acquire → Pursuit → Settle 规划，并通过既有鼠标驱动接口发包。

`FRESH_HEAD` 才能创建新的闭环运动债务。`PREDICTED`/`HELD` 最多维持身份并在
30 ms 内衰减排空已有安全债务，不能新增前馈、响应学习或自动触发。身体检测只可
辅助维持身份，默认不直接作为控制点。

## 20 秒响应标定

普通用户按以下顺序操作：

1. 本机游戏用户保持“调节 > 云机（可选）”关闭，可直接启动，不需要云机参数或标定。
2. 云机用户在同一组里明确开启，并填写平台名称（任意非空名称），再按云机游戏和 GHUB 的当前设置填写画面宽、画面高、DPI 和游戏内灵敏度。
3. 在该组底部点击“开始约20秒标定”。标定只展示训练场操作说明，不再弹出第二套参数输入。
4. 进入训练场，找一个站着不动的训练机器人，把准星放在它的头部附近。
5. 确认后按 `Alt + Tab` 切回游戏。不会抢占输入焦点的独立置顶窗口会先给出 5 秒准备倒计时，然后进入最长 20 秒的测量窗口；有效双向样本提前齐备时会提前完成。
6. 切回游戏后松开键盘和鼠标：不移动鼠标、不按方向键、不移动人物、不主动转镜头。准星被探测包轻微带动是正常现象。

真实拓扑是 VisionForge、GHUB 和云机客户端（如顺网/Airlinks 客户端）都运行在用户本地主机，游戏运行在远端云电脑。
标定测量“本地相对输入 → 云端游戏消费 → 远端渲染 → 画面回传本地”的端到端响应；环境检测只读取
本机精确客户端进程和本机可见窗口，绝不依赖或尝试读取云电脑进程。

短暂没看到头部、一帧预测目标或一次未观测到反馈只会暂停当前探测并继续重试，不会让整次标定立即结束。
标定会发送低幅度、X/Y 分轴、正反对称 GHUB 探测包，估计：

- X/Y `px/count`；
- 输入到画面的延迟 P50/P95；
- 视觉噪声与标定置信度。

结果按以下环境指纹保存：云平台、驱动模式、分辨率、DPI、游戏灵敏度和标定版本。
任一字段变化后必须重新标定。成功后标定画像自动落盘，GUI 自动启动正常模式，无需开发人员人工处理。
标定只能由 GUI 的一次性操作或显式 `--calibrate-response on` 启动；磁盘中残留的
`calibration_requested` 字段会被普通启动和热重载忽略，不能静默创建标定会话。GUI
每次拉起核心都会明确传入 `on` 或 `off`，因此“本次标定”和“普通运行”不存在模糊继承。
标定以运行主循环首次轮询为用户可见计时起点，以实际驱动调用成功的单调时间计算单个探测的延迟；发送前已
进入流水线的画面不能被误算为响应。启动时的有效策略哈希同时覆盖 X/Y 增益、
P50/P95 延迟、噪声、置信度和画像版本；画像变化必然生成新的哈希。

标定期间仅允许带稳定身份的原始 `FRESH_HEAD` 观测绕过普通按键门控；身体、预测和保持
目标都不能发起探测。探测从 ±1/±2 count 开始，仅当云端链路吞掉小包时才按
±4/±8/±12 count 有界升级；单包绝不超过正常控制安全上限和标定专用 12 count 上限。
一个轴完整扫掠仍无响应时会明确失败，不会无限重复 X 轴。每个探测会观察完整的 400 ms
响应窗口，使用同幅度正反配对校验增益和方向；已通过质量校验的延迟尾样本会以 nearest-rank
进入 P95，不会被 MAD 裁剪或线性插值掩盖。若只有最大安全探针量能被链路消费，该最大正反对
会重复一次以满足一致性验证。任何探针可能发出后若目标身份变化，本轮立即以强类型失败结束，
不会重新从同方向探针开始累积漂移。画像使用 v3 契约原子写入；只有本轮同时报告
`COMPLETE`、`profile_saved=true`、`profile_verified=true`，且 GUI 能按当前环境指纹严格读回同一
可信画像，才显示完成并自动启动。历史画像或单独的完成退出码都不能冒充本轮成功。可信画像的
延迟 P95 上限为 175 ms，覆盖当前 0–150 ms 验证范围及容差。

标定失败会安全退出且不生成伪造画像。活动的云闭环缺少完全匹配画像时，运行时会在创建检测器和
控制器之前 fail-closed 退出，并记录 `cloud_response_calibration_needed`，不会退回固定增益继续发包。
此外，检测到“顺网/Airlinks 精确客户端进程 + 可见顶层窗口”时，只要屏幕视觉控制会实际发输入，
即使用户漏开云闭环或环境字段不完整，也会明确引导并阻止 legacy 激进运行。仅有后台残留进程、
`control.enabled=false`、`control.mode=none` 或非屏幕源都不会阻止；ToDesk、GameViewer、虚拟显示器和
普通本机游戏进程也不作为强信号。最小化但仍由 Win32 报告为可见的云客户端窗口仍按活动客户端处理。
GUI 的显式标定启动路径不受画像缺失门禁阻挡。一次启动只读取一份画像快照，并把同一对象用于
策略哈希、门禁与控制器，避免日志策略和实际控制参数错位。

## 运行时安全边界

- 捕获线程可维持高帧率，但只有新的可信视觉测量能增加运动债务。
- 电机循环仅有限排空；未看到同方向累计视觉进展前，不会按时间自动释放全部预算。
- 在线响应学习仅接受同一 `FRESH_HEAD`、高置信、低目标加速度片段，并用滑动中位数
  与 MAD 拒绝异常值；估计达到边界后仍可由稳定样本恢复。
- 无视觉进展窗口为 `max(2 × latency_p95, 120 ms)`。若预期位移已超过噪声而误差改善
  率不足 15%，立即取消该目标债务并暂停，直到可信进展或新身份出现。
- Acquire 不添加人为反应延迟；Pursuit 才允许有界延迟前馈，并在同锁 120 ms 后装饰
  个人轨迹；Settle 使用临界阻尼与滞回，安全半径内个人扰动为零。进入 Settle 的判断
  同时考虑已在途包的预计位移，因此会在下一幅云端画面预计进入 `R` 时提前制动；
  `max(0.5R, 1.25Q)` 内归零，避免多等一个云端往返后才刹车。

## 完整回放录制

普通运行保持采样日志。正式验收前，仅在短时训练场会话把以下开关设为 `true`：

```yaml
control:
  replay_telemetry_complete: true
```

完整模式逐条记录 `control/submit`、锁生命周期和成功的 `hid/move`，并携带
`replay_complete`、`controller_seq`、`packet_index`、`lock_start`。submit 在目标状态
对电机线程可见之前记录，保证同序列的第一个 HID 包不能抢先。录制完成后应关闭该
开关，避免长期高频日志开销。

执行只读验收：

```powershell
python tools/evaluate_control_replay.py --json <trace.db>
```

工具以只读 SQLite 连接工作，并采用 fail-closed 语义：缺字段、采样日志、包号缺 0、
跳号、重复或乱序均为 `UNAVAILABLE`，不会被误报为 PASS。旧日志仍会输出 observed
统计，但不能作为正式门禁结论。

离线云闭环压力测试：

```powershell
python tools/simulate_cloud_control.py --assert --compact
```

它覆盖多组增益、0–150 ms 延迟、60–240 FPS、抖动、丢帧、静态无进展和目标反向。
真实云机（如顺网云）验收仍须使用匹配环境指纹的新标定画像和完整训练场 trace。
