# R3 端到端故障模型与恢复语义

| 阶段 | 主要故障 | 必须响应 | 禁止行为 |
|---|---|---|---|
| Host epoch 建立 | 状态文件损坏、锁失败、空间耗尽 | 停止会话并记录明确阶段 | 回退随机 epoch 后继续发送 |
| DXGI 捕获 | WAIT_TIMEOUT | 继续等待并维持会话 | 当作设备丢失重建全部管线 |
| DXGI 捕获 | ACCESS_LOST/设备移除 | 有界重建并预留新 epoch | 沿用旧参考链和旧 epoch |
| 编码 | 编码器重建、IDR 请求 | 生成 IDR 并等待完整发布 | 仅编码成功就确认 IDR |
| UDP 发布 | 部分分片、socket 错误 | 保持恢复请求、不得确认参考链 | 将部分发布计为完整帧 |
| UDP 接收 | 乱序、重复 | 幂等重组 | 重复分片重复累计字节 |
| UDP 接收 | 同索引不同内容 | 丢弃整帧、计数并请求恢复 | 选择任一版本继续解码 |
| 资源边界 | 在途帧/字节超限 | 淘汰并 fail-closed | 无界缓存或阻塞网络线程 |
| epoch 切换 | 未来 epoch 零散分片 | 仅作为候选，不替换活动流 | 单个分片直接切会话 |
| epoch 回滚 | 退休/较低 epoch | 永久拒绝 | 有限历史淘汰后重新激活 |
| MediaCodec | 重建期间又收到新 epoch | 合并到最新目标 | 启动多个竞争重建或退出接收线程 |
| 推理 | 结果过期、generation 不匹配 | 丢弃并阻断控制 | 将旧推理映射到新画面 |
| 控制 ticket | late/重复 ACK | 忽略并计数 | 完成当前或后续 ticket |
| ACK 可见性 | 未观察到更新完整帧身份 | 保持阻断并触发恢复 | 仅凭时间戳或超时自动放行 |
| Bluetooth/USB | 设备断开、回调乱序 | 关闭输出并幂等 reconcile | 旧回调重新开启输出 |
| SQLite schema | 无害格式差异 | token 规范化后接受 | 使用脆弱字符串格式比较 |
| SQLite schema | 约束缺失/弱表预建 | 明确拒绝并停止业务启动 | 自动“修补”后把不可信表当安全表 |
| Sidecar outbox | worker 崩溃、重复领取 | 租约、幂等键、重试/终态 | 网络请求进入支付事务或假成功 |

恢复策略的共同原则是：**宁可停止对应能力，也不跨越无法证明安全的状态边界。**
