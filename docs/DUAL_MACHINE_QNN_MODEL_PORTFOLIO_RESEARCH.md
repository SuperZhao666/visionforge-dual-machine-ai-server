# 双机移动端 QNN 模型组合实测报告

日期：2026-07-22  
设备：Xiaomi 23116PN5BC / Snapdragon 8 Gen 3（代号 `shennong`）  
后端：Qualcomm QAIRT 2.37.1 / QNN HTP  
数据：`images1`、`images2`、`images3`，合计 1068 帧、1082 个人体框

## 结论

目前不应把 `F:\瓦` 中的任一已购模型作为“高精度模式”接入正式 APP。

现有 `V11 320 瓦洛兰特超k神升级进化版本模型破加密.onnx` 的 QNN HTP W8A16 版本，在相同手机、相同 1068 帧、相同预处理、阈值和 NMS 下，精度明显优于本轮最有希望的 `wa-v8-256.onnx`。后者虽然速度满足目标，但会让人体检测精度下降，不符合“牺牲部分速度换更高精度”的产品定义。

推荐暂时只保留当前 320 N 模型，不向用户暴露一个名不副实的“高精度”选项。等拿到与真实游戏画面分布一致、且经相同评估协议验证优于基线的模型后，再接入模型档位选择。

## 真机同条件对比

固定评估口径：RGB、模型静态输入尺寸、置信度阈值 0.25、NMS IoU 0.45、人体框匹配 IoU 0.50。

| 模型 | QNN 格式 | 输入 | TP / FP / FN | Precision | Recall | F1 | 平均匹配 IoU | 1068 帧 runner 墙钟 | runner 吞吐 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 当前基线 V11n | W8A16，拆分 FP32 输出 | 320 | 1021 / 59 / 61 | 0.9454 | 0.9436 | **0.9445** | **0.7766** | 3.305 s | **323.1 FPS** |
| `wa-v8-256` P2 | W8A16，拆分 FP32 输出 | 256 | 927 / 141 / 155 | 0.8680 | 0.8567 | 0.8623 | 0.7025 | 4.822 s | 221.5 FPS |

这里的 runner 墙钟包含逐样本原始张量读取、QNN 图执行和 FP32 输出文件写入，但不包含视频解码、图像预处理、NMS、业务控制和网络传输。因此它用于同条件模型比较，不能直接当作正式 APP 的端到端 FPS。

QNN optrace 显示 `wa-v8-256` 的纯 HTP accelerator execute 均值约 2.47 ms，即约 405 FPS 的硬件图执行能力。它的 5440 个候选锚点和三类 FP32 输出导致 runner 文件 I/O 明显高于基线的 2100 个锚点，因此 runner 吞吐只有约 221.5 FPS。

## 说明书核验

- 红色模型 README 明确写明：YOLOv11，类别 0 为身体、类别 1 为头部；`v11n` 面向低配置/低精度，`v11s` 面向高配置/高精度，并建议优先降低分辨率而不是直接改用 n。
- `使用说明（新手必看）` 下的三个文本文件实际内容都只有 `123`，文件名虽声明大部分为黄色、少部分为红色，以及道具可能在类别 3 或其他类别，但不能替代可执行的类别契约。
- 若模型类别、颜色域和输出协议不能被可靠识别，就不能直接加入正式 APP 的用户选项。

## 为什么参数更多没有变得更准

模型参数量和输入尺寸只决定容量与计算量，不保证在当前数据域更准。已购的 YOLO11s 模型很可能训练于不同颜色轮廓、不同画面设置、不同类别定义或不同标注风格。当前 1068 帧均为黄色轮廓数据；域不匹配时，9M 或 11M 参数模型也会明显输给匹配当前画面分布的 2.58M 基线。

## 正式接入的硬性门槛

新的“高精度模式”至少必须同时满足：

1. 在三套 1068 帧固定回归集上，F1、AP50 和 mAP50-95 均高于当前基线，不只看单张图或单一 Recall。
2. 使用实际交付的 QNN HTP 量化产物评估，不能拿 FP32 ONNX 指标代替量化后指标。
3. 手机端完整推理阶段稳定中位数不低于约 200 FPS；同时报告 P95、热降频和端到端延迟。
4. 类别映射明确，至少可靠定义人体与头部；道具、背闪等额外类别必须由独立配置契约描述。
5. 主机 ROI、编码尺寸、手机解码、预处理、QNN 输入、锚点数和后处理都由同一个模型 Profile 驱动，禁止只替换模型文件。

## 下一版建议

真正可行的高精度档不是继续盲试现有买来的权重，而是以当前 320 N 的同域数据为基础训练或蒸馏一个 YOLO11s/YOLO11m 级别模型，再按 W8A16 校准并在真机回归。目标可以设为：相对当前基线 F1 至少提升 1 个百分点、mAP50-95 至少提升 2 个百分点，并在移动端完整推理阶段保持不低于 200 FPS。未达到这三个门槛时，不发布该档位。
