# 威胁模型

## 核心资产

- 用户、订单、时长、授权和日志数据库。
- 授权签名私钥、应用密钥、支付/邮件/API 凭据。
- 生产代码、发布产物、审计日志和备份。
- QQ Steward 的管理凭据、模型 API Key 与项目知识库。

## 主要威胁与控制

| 威胁 | 主要控制 | 验证证据 |
|---|---|---|
| SSH 密码喷洒或旧版本漏洞 | 安全更新、密钥登录、关闭 root/密码登录、安全组限源、CrowdSec | 包版本、`sshd -T`、外部端口测试、封禁决策 |
| Web 扫描、注入、暴力破解 | Nginx 限速、最小请求体、CrowdSec 日志检测/AppSec 分阶段启用 | Nginx 配置测试、检测日志、无害规则测试 |
| 内部端口或 Docker 端口误暴露 | 仅回环绑定、安全组、INPUT 与 FORWARD/DOCKER-USER 双重检查 | `ss -lntup`、Docker 端口、外部有限扫描 |
| 凭据泄漏 | 不入仓库、文件最小权限、短期凭据、轮换、日志脱敏 | Secret 扫描、权限清单、轮换记录 |
| 服务器失陷后清日志/删数据 | 异机加密日志与备份、最小权限、FIM、恢复演练 | 远端副本、校验和、恢复演练记录 |
| 防御组件误封导致业务中断 | 先检测后阻断、白名单、单一规则所有者、自动回滚 | 观察期报告、业务烟测、回滚演练 |
| 供应链投毒 | 固定版本/提交/摘要、校验签名、最小下载源、禁用 `latest` | `sources.lock.json`、SHA-256、签名验证 |

## 明确不做

- 不对第三方目标扫描、利用、爆破或攻击。
- 不在生产机运行高负载漏洞扫描器或全套 SIEM。
- 不声称“绝对安全”；目标是降低概率、缩小爆炸半径并提高发现/恢复速度。
