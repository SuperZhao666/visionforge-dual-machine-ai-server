# 防御架构与边界

## 分层

1. 接入层：腾讯云安全组、主机防火墙、Nginx、TLS。
2. 检测与响应层：CrowdSec Engine 读取公开日志，由单一 bouncer 执行封禁。
3. 业务层：现有 FastAPI 与 QQ Steward；安全组件只通过日志、公开健康检查和进程边界观察，不导入业务模块。
4. 数据层：SQLite、密钥、上传日志和发布文件；安全流程只做一致性备份与权限校验。
5. 基础设施层：Ubuntu、systemd、Docker、journald/auditd、证书续期。

依赖严格向下：业务不依赖 CrowdSec/Lynis；检测组件不直接修改业务数据库；防火墙只接受一个主动规则所有者。

## 加密边界

- 客户端到 Nginx：TLS 1.2/1.3，自动续期和到期告警。
- Nginx 到同机应用：回环或 Unix Socket，不发布到公网；同机回环不额外制造证书管理面。
- 跨主机上游：HTTPS/mTLS，必须启用上游证书与主机名校验。
- 管理面：SSH 密钥；安全组只允许固定管理源或 VPN/堡垒机。
- 备份：必须异机、加密并定期恢复演练；同机副本只用于短时回滚，不算灾备。

## QQ 机器人隔离契约

- 机器人模块、镜像、环境变量和 Docker 网络由其独立任务维护。
- 管理/API 端口只绑定 `127.0.0.1`，不得使用 `0.0.0.0` 发布。
- 安全任务不得重建机器人容器、修改其数据卷或读取其密钥。
- 防火墙变更前记录容器名、端口和 Docker 网络；验证 `DOCKER-USER` 或 nftables 等效链。
