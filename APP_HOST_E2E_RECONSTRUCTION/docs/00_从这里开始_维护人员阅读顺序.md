# VisionForge App / Host 端到端重建：维护人员阅读顺序

本目录是本次确定性重建的总入口。源码并非从文字说明“猜测出一个示例工程”，而是以已验证的 `VisionForge_DualMachineAI_Server_complete_repair.zip` 完整源码树为基线，将丢失三小时任务留下的路径、行为、测试与交付说明逐项回放到真实工程中。

建议阅读顺序：

1. `SOURCE_RECONSTRUCTION_PROVENANCE.md`：先理解哪些材料真实存在、哪些原始字节已经丢失，以及本次如何避免冒充“原样找回”。
2. `FINAL_REPAIR_REPORT_zh-CN.md`：查看 Android、Host、传输协议、解码恢复和控制链的实际代码改动。
3. `APP_HOST_E2E_REPAIR_LEDGER.json`：逐项核对“历史结论 → 实现文件 → 测试/门禁证据”。
4. `TEST_MATRIX.md`：区分 `PASS`、`NOT_RUN_ENVIRONMENT` 与 `NOT_RUN_EXTERNAL`。
5. `INCIDENT_NON_REGRESSION.md`：了解检查点、Git、ZIP、哈希与 Drive 回读要求。
6. `EXTERNAL_ACCEPTANCE.md`：在 Windows、Android、QNN、MAKCU、Bluetooth 和真实网络环境执行现场验收。
7. 仓库根目录 `docs/APP_HOST_ARCHITECTURE_zh-CN.md`、`docs/HOST_APP_E2E_STREAMING_zh-CN.md` 与 `docs/MOBILE_CONTROL_STATE_zh-CN.md`：进入长期维护设计。

可移植验证入口：

```bash
tools/run_app_host_e2e_portable_checks.sh
```

该命令执行架构门禁、跨语言协议门禁、检查器自测、C++20 Release 构建与 CTest、完整纯 Java 回归以及关键分层 Java 严格编译。它不替代真实 Android SDK/NDK、Windows DXGI/NVENC、QNN/HTP 或物理控制设备验收。
