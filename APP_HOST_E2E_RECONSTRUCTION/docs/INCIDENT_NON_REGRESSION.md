# 丢失交付事故的强制防复发规则

## 1. 阶段检查点

每一大阶段必须同时具备：

- Git commit；
- 可应用 patch；
- 机器可读测试结果；
- 日志；
- 原始输入哈希；
- 本阶段状态说明。

任何仅存在于未提交工作树中的大规模改动都不能称为可恢复成果。

## 2. 最终包原子生成

最终包只能从一个干净暂存目录生成：

1. 从最终 Git HEAD 导出源码；
2. 注入 Git bundle、patch、报告、日志和输入证据；
3. 排除 `.git`、构建缓存、真实 `.env`、私钥、keystore、本机 SDK 路径和字体二进制；
4. 生成逐文件 SHA-256 清单；
5. 生成单一根目录 ZIP；
6. 执行 CRC、路径穿越、符号链接、敏感文件和条目清单检查；
7. 解压到全新目录并逐文件比较。

## 3. Drive 备份完成条件

仅调用上传接口不算完成。必须：

1. 列出目标文件夹并看到准确文件名；
2. 读取 Drive 元数据中的大小；
3. 从 Drive 下载原始 ZIP；
4. 比较本地与回读副本的字节数和 SHA-256；
5. 对回读副本重新做 ZIP CRC 和内部清单验证。

任一步失败时，状态只能写 `UPLOAD_OR_READBACK_FAILED`，禁止写“已备份”。

## 4. 声明边界

- “源码重建完成”必须有源码路径和测试证据；
- “完整 ZIP”必须有真实体量、条目数、CRC、清单和解压回读；
- “真机通过”必须有对应设备日志；
- “零缺陷”不作为工程验收术语；使用已验证范围和剩余风险描述。
